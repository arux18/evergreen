# Intentional Seams

**Category:** Generative UI — Agency  
**Layer:** Visual Design / Affordances  
**Status:** Emerging law — generative UI specific

---

## Definition

AI-generated components must include visible joints — subtle but deliberate signals that show users where they can intervene, edit, regenerate, or override. Without seams, users either over-trust the output (treating it as fixed and authoritative) or feel locked out (unable to act on it). Seams are the generative UI equivalent of affordances.

---

## Core Principle

In traditional UI, affordances communicate what's interactive — a button looks pressable, a text field looks editable, a link looks clickable. These are physical metaphors mapped to digital surfaces.

In generative UI, the interaction model is more abstract. The AI produces output that *looks* designed and complete. There are no obvious handles, no clear edit points, no visible history of how it got there. Users lose the sense that they can act on it.

Intentional seams restore that sense of agency. They say: *this was generated, you can change it, here's how.*

---

## The Three Types of Seams

### 1. Generative boundary seams
Visual signals that mark where AI-generated content begins and ends within the larger interface.

**Purpose:** Tell users which parts of the UI are static (shell) and which are generated (canvas).

**Patterns:**
- Subtle background differentiation between shell and canvas zones
- A thin rule or border at the top of the generated content area
- A "generated by AI" label or icon at the boundary — understated, not alarming
- A dashed or dotted border style to signal "this zone is dynamic"

### 2. Component-level action seams
Affordances attached to individual generated components that expose what can be done to them.

**Purpose:** Give users control over specific generated elements without requiring them to regenerate everything.

**Patterns:**
- Edit icon (pencil) on hover that allows the user to modify the component's parameters
- Regenerate icon (refresh) that replaces just this component
- Feedback icons (thumbs up/down) that signal quality to the system
- "Lock" icon that prevents a component from being affected by future regeneration
- Expand/collapse for generated explanations or detail panels

### 3. Input provenance seams
Signals that connect a generated output back to the input that produced it.

**Purpose:** Help users understand why they got what they got — and how to change it.

**Patterns:**
- "Generated from: [your inputs]" summary above or beside the output
- Highlighted or annotated reference to the parameters that most influenced the output
- "Edit inputs" shortcut that returns to the configuration state without clearing the output

## Design Decisions

### Seams should be subtle, not alarming
A seam that screams "THIS IS AI" breaks trust and feels defensive. A seam that whispers "you can edit this" feels empowering. The goal is agency, not disclaimer.

**Calibration:**
- Default: seams are visible on hover or focus only
- On first use or for new users: seams are more persistent until familiarity is established
- For high-stakes outputs (financial data, medical, legal): seams may be more persistent as a trust signal

### Seams live at the intersection of shell and canvas
The most important seam is the boundary between the persistent shell (Layer 2) and the generative canvas (Layer 3). This seam is architectural — it should be defined in the design system, not designed per-screen.

### Seams must be consistent
If a pencil icon means "edit this component" in one part of the product, it must mean the same thing everywhere. Inconsistent seam patterns break the mental model and cause users to stop trusting the signals.

### Not every generated element needs every seam type
Design seams proportional to the stakes of the content:
- High-stakes (financial projections, legal summaries) → persistent seams, clear provenance
- Medium-stakes (recommendations, insights) → hover seams, component actions
- Low-stakes (labels, descriptions) → minimal or no seams

---

## Seam States

| State | Seam Behavior |
|---|---|
| Default | Subtle boundary marker; component actions hidden |
| Hover / focus | Component action icons appear; boundary marker strengthens |
| Active edit | Component enters edit mode; boundary marker clearly active |
| Locked | Lock icon visible; component marked as excluded from regeneration |
| High-stakes content | Persistent seams; provenance summary always visible |

---

## Evergreen Application

- Generated financial projections should show a subtle provenance summary: "Based on: $2M portfolio, 7% return, 20yr horizon"
- On hover, each generated chart or insight card should reveal an edit icon (to adjust parameters) and a regenerate icon (to get a new version of just that component)
- The boundary between the persistent sidebar nav and the generated response area is the primary architectural seam — define it once in the design system
- For HNW clients: provenance seams are a trust feature, not a UI detail. Showing "this projection was generated using your actual Evergreen portfolio data" reduces skepticism significantly
- Locked components ("I want to keep this scenario unchanged") are important for comparison workflows — clients may want to hold one scenario steady while iterating on another

---

## Related Laws

- **Output Anchoring** — seams mark the boundary between shell layers and canvas
- **Reversibility** — seams are where regenerate and undo affordances live
- **Calibrated Trust** — seams are a primary mechanism for building appropriate trust
- **Interpretability** — input provenance seams are the visual implementation of interpretability

---

## Anti-Patterns

- No visible signal that content was AI-generated
- Edit/regenerate affordances buried in menus or not present at all
- Inconsistent seam patterns across different generated components
- Seams that are too prominent — "AI Generated" banners that feel like disclaimers
- No way to modify just one component without regenerating everything
- Generated content that looks identical to static/hardcoded content with no distinguishing signal
- Provenance hidden or inaccessible — no way for the user to understand why they got what they got
